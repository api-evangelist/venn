# Venn

> Venn is a multifamily resident-experience operating system for owner-operators:
> a resident mobile app, an operator dashboard, and a single data layer over leasing,
> onboarding, living, renewals and an AI concierge, synced with the property
> management systems of record (Yardi, RealPage, Entrata, AppFolio). Founded 2016,
> co-headquartered in New York and Tel Aviv.

This file was GENERATED by API Evangelist from public sources. Venn does not

answers 200 with an HTML shell for every path including one that cannot exist.

## What Venn actually exposes

- Venn has a real, unversioned GraphQL API at https://api.venn.city/production/graphql
  (Apollo Federation gateway, AWS API Gateway edge).
- **Anonymous introspection is enabled** on that endpoint: 1,983 types, 320 query
  fields, 357 mutation fields, no subscriptions. The contract is readable.
- **Data is not.** An unauthenticated read returns `VennUnknownError` from the
  `persistency` subgraph. Auth is a bearer JWT from Venn's AWS Cognito user pool.
- There is **no developer portal, no API reference, no OpenAPI, no AsyncAPI, no
  webhook catalog, no MCP server, no agent card, no sandbox, no published rate
  limits and no published pricing.** Every one of those was probed in this pass.

## Notes for agents

- Every GraphQL error returns HTTP 200. Branch on `errors[].extensions.code`,
  never on the status line.
- `first` or `last` is mandatory on every list field, or the gateway rejects the
  query with `pagination_enforce_error`.
- Idempotency exists on exactly one entity (`Notification.idempotencyKey`). Every
  other write — payments, bookings, broadcasts, contracts — is unprotected against
  retry. Query before you retry.
- Deletes are soft (`deleted` / `deletedAt`). No restore mutation and no retention
  window is published.
- Reversal operations exist (`cancelBooking`, `cancelSubscriptionContract`,
  `requestCancelationServiceProductOrder`) but no window is documented for any of
  them. Do not assume one.
